# 0007. フォルダの概念をコード上でも notebook と呼ぶ

- 状態: 承認
- 日付: 2026-09-28

## 背景
基本設計書 1.3 では「内部（コード・DB）ではフォルダ（folder）、UI 上はノートブック」と、1つの概念に2つの名前を付けていた。
1つの概念に2つの名前があると、コードを読むたびに頭の中で「folder ＝ ノートブック」と翻訳が必要になり、UI の仕様とコードの対応も追いにくくなる。

## 決定
コード・DB・設計書のすべてで **notebook（ノートブック）** と呼ぶ。テーブル名は `notebooks`、型は `Notebook`、ノートの所属は `notebookId`。ルート（どのノートブックにも属さない場所）は **library（ライブラリ）** と呼び、`notebookId = null` で表す。

## 検討した選択肢
- 基本設計どおり folder のまま — 実装としては素直だが、UI とコードで言葉がずれ続ける

## 結果
- UI・仕様・コードが同じ言葉になる
- 基本設計書 1.3 の用語表と 5 章の `folders` / `folder_id` はこの ADR で置き換える
- 要件定義書の「フォルダ」（FR-F-xx）は要件の言葉としてそのまま残す（ノートブック＝要件上のフォルダ）
