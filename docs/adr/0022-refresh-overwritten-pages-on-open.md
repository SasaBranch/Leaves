# 0022. 上書きされたページ画像は、ノートを開いたときに確かめて反映する

- 状態: 承認
- 日付: 2026-09-28

## 背景
ADR 0020 では、画像ファイルの中身だけを外部で上書きした場合は反映しないとした（フォルダの更新日時が変わらず、走査で気づけないため）。しかし上書きすると、次のような食い違いが起きる（利用者からの指摘）。

- ページ画像は同じ場所から読むので新しい画像が出るが、サムネイル（`.leaves/` に別に作ったもの）は古いまま
- 文字認識の結果（検索・テキスト表示・PDF の透明テキスト）は古い画像のまま
- expo-image は URI ごとにキャッシュするため、場所が同じ新しい画像を出さないことがある

## 決定
- **ノートを開いたとき**（ノート表示 SC-5）に、そのノートのページのファイルサイズ・更新日時を `.leaves.json` の記録と比べる（`services/sync/refreshReplacedPages.ts`）
- 変わっていたページは、サムネイルを作り直し、画像の大きさを読み直し、文字認識を「認識待ち」に戻してやり直す。`.leaves.json` → DB の順に反映し、ノートの更新日時を進める
- 保存済みの画像の表示には、ノートの更新日時を含めたキャッシュのキーを付ける（`ui/imageSource.ts`）。差し替え後に古い画像を出し続けないため

## 検討した選択肢
- **外部変更の反映（起動時・前面復帰時）で全ページのファイル情報を確かめる** — ノート1,000件・ページ5,000枚で数秒遅くなる（ADR 0021 の計測で、ファイル情報の読み込みは全体の走査の大半を占める）
- **ノート表示に「再読み込み」ボタンを置く** — 利用者が上書きしたことを覚えている必要があり、気づかないまま古い検索結果が残る

## 結果
- 開いたノートの分（数ファイル）だけ確かめるので、起動・前面復帰の速さは変わらない
- ノートを一度開くまでは、一覧の表紙（サムネイル）と検索結果は古いまま。検索結果の行のサムネイルは、アプリを再起動するまで古い画像が出ることがある
