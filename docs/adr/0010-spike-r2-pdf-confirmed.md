# 0010. 事前検証 R-2 の結果、pdf-lib による透明テキスト付き PDF を採用する

- 状態: 承認
- 日付: 2026-09-28

## 背景
ADR 0006 で、PDF に OCR テキストを不可視テキストとして埋め込むこと、pdf-lib が 2022 年以降更新されていないことを承知で採用することを決め、生成時間・メモリ・実際に検索できるかを検証することにしていた（#3）。

## 検証内容
`spikes/r2-pdf-invisible-text.js` で、詳細設計書 9.5 の計算（A4 幅、相対座標 → PDF 座標、文字サイズ＝行の高さ × 0.85、水平拡大率 `Tz` で行幅に合わせる、描画モード `Tr 3`）をそのまま実装し、Node.js（Mac）で計測した。

| 項目 | 結果 |
|---|---|
| 条件 | 10ページ（画像 1800×2400 JPEG）・日本語 2,000 文字 |
| フォント | `@expo-google-fonts/noto-sans-jp` の NotoSansJP_400Regular.ttf（5.2MB）を `subset: true` で埋め込み |
| 生成時間 | 初回 36ms、2回目以降 19ms |
| 出力サイズ | 302KB（画像 279KB ＋ サブセットフォント等 約 23KB） |
| メモリ | ヒープ増加 約 5MB |
| 文字の取り出し | `pdftotext` / pypdf で日本語が行ごとに正しく取り出せた |
| 見た目 | ページを画像化すると元画像のみが表示され、テキストは見えない |

## 決定
ADR 0006 の方式（pdf-lib ＋ fontkit、低水準演算子で `Tr 3` / `Tz`）を採用する。フォントは `@expo-google-fonts/noto-sans-jp` の 400 Regular を使う。

## 結果
- 性能・サイズとも問題ない。スマホ（Hermes）で10倍遅くても 1 秒未満
- 未検証として残るのは React Native 上での動作（フォントファイルを `Uint8Array` として読み込む方法、Hermes 上の fontkit の動作）。PDF 書き出しの実装（#29）の最初に確認する
