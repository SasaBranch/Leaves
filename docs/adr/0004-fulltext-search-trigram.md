# 0004. 全文検索に FTS5 trigram を使い、検索経路を1本にする

- 状態: 承認
- 日付: 2026-09-28

## 背景
日本語は単語の区切りがないため、SQLite FTS5 の標準トークナイザでは部分一致検索ができない。要件（FR-Q-02）では1文字のキーワードでも検索できる必要がある。

基本設計書 5.3 では「3文字以上は FTS5、1〜2文字は通常テーブルへの LIKE」と2つの検索方式を切り替える設計にしていた。

## 決定
FTS5 の trigram トークナイザで `pages_fts` を作り、**検索はすべて `pages_fts` に対する LIKE で行う**。trigram テーブルへの LIKE は、3文字以上なら索引を使って高速に、3文字未満なら全件走査で（遅いが正しく）動く。

## 検討した選択肢
- 基本設計どおり、キーワード長で2つの方式を切り替える — 同じ「検索する」という知識が2か所に分かれ、並び順・範囲指定・ハイライトの処理も2重になる
- 2-gram を自前で生成して標準 FTS5 に格納 — 1文字検索はやはり別処理が必要で、生成処理の保守も増える
- 形態素解析 — 辞書の同梱が必要で、手書き OCR の誤認識文字列と相性が悪い

## 結果
- 検索のコードが1本になる（基本設計書 5.3 の2方式切り替えを置き換える）
- 1〜2文字の検索は全件走査になる。ページ5,000枚で1秒以内（NFR-P-03）に収まるかを実装初期に検証する（基本設計書 R-1）。収まらない場合は新しい ADR で方式を見直す
- 同梱 SQLite で trigram が使えることが前提（同じく R-1 で検証）
