## 1. 目的・背景

### 1.1 背景
紙のノートや手書きメモは、書いた後に「どこに書いたか分からない」「持ち歩けない」「検索できない」という問題がある。既存のスキャンアプリ（Microsoft Lens 等）は撮影品質は高いが整理機能が弱く、ノート管理アプリ（Obsidian 等）は整理機能は強いが紙の取り込みが手間である。

### 1.2 目的
紙のノートを **すばやく撮影・デジタル化** し、**フォルダ階層で整理** し、**文字で検索** できるスマホアプリ「Leaves」を開発する。

### 1.3 名称の由来
紙の一葉（leaf）がフォルダ階層という木の枝に集まっていくイメージから「Leaves」とする。

## 2. スコープ

### 2.1 対象範囲（MVP）
- ドキュメントスキャン（撮影・輪郭検出・台形補正・複数ページ）
- 写真アプリからの画像取り込み
- 端末内OCR（日本語・英語）
- 階層フォルダによるノート管理
- ノート内ページの追加・並べ替え・削除
- 全文検索（タイトル・OCRテキスト）
- ノートのエクスポート（PDF / Markdown）
- 本棚（ノートブック一式の保存単位）の作成・切り替え・名前変更・削除
- ファイルとしての保存（「ファイル」アプリ・Finder から見える）と、外部での変更の反映

### 2.2 対象外（MVPでは実装しない）
- 複数端末間の同期・クラウド保存
- Obsidian 等の外部アプリとの連携
- ユーザーアカウント・ログイン
- ストア（App Store / Google Play）での公開
- バックアップ／復元、アプリロック、ゴミ箱
- タグ、メモの Markdown 編集
- OCRテキストの手動修正
- 取り込み画像の後からのトリミング・フィルタ適用

※ 対象外機能は「10. 将来拡張」で扱う。

## 3. 用語定義

| 用語 | 定義 |
|---|---|
| ノート | 1回のスキャン（または取り込み）で作成される管理単位。1枚以上のページを持つ |
| ページ | ノートを構成する1枚の画像と、そのOCRテキスト |
| フォルダ | ノートおよび他のフォルダを格納する入れ物。無制限に入れ子にできる |
| ルート | 本棚の最上位の階層。フォルダにもノートを直接置ける |
| 本棚 | フォルダ・ノート一式をまとめた保存単位（Obsidian の Vault に相当）。端末上の1つのフォルダに対応し、本棚ごとにデータは独立している。複数作成して切り替えられる |
| 外部変更 | 「ファイル」アプリや Finder など、Leaves 以外から本棚フォルダの中身が変更されること |
| スキャン | カメラで撮影し、輪郭検出・台形補正を行って画像を得る操作 |
| 取り込み | 写真アプリ（フォトライブラリ）の既存画像をノートとして保存する操作 |
| OCR | 画像から文字を認識してテキスト化する処理（Optical Character Recognition） |
| MVP | Minimum Viable Product。最初にリリースする最小限の機能セット |

## 4. 利用者・利用シーン

### 4.1 想定利用者
- 手書きノート・メモ・書類・プリントなど、紙の情報を日常的に扱う人（用途は限定しない）
- 当面は開発者本人が利用者（ストア公開はしない）

### 4.2 代表的な利用シーン

| No | シーン | 流れ |
|---|---|---|
| S-1 | 授業・会議の後にノートを取り込む | 該当フォルダを開く → スキャン → 複数ページ撮影 → 保存 |
| S-2 | 配布プリントを保存する | スキャン → 保存 → 後でフォルダに移動 |
| S-3 | 以前撮った写真をノート化する | 写真アプリから取り込み → 保存 |
| S-4 | 以前のメモを探す | 検索画面でキーワード入力 → 該当ページを表示 |
| S-5 | ノートを人に渡す | ノートを開く → PDFで書き出し → 共有シートで送信 |
| S-6 | 撮り忘れたページを足す | 既存ノートを開く → ページ追加（スキャン） → 並べ替え |

## 5. 機能要件

優先度: **Must** = MVPに必須 / **Should** = MVPで可能なら実装

### 5.1 フォルダ管理

| ID | 要件 | 優先度 |
|---|---|---|
| FR-F-01 | ルート配下にフォルダを作成できる | Must |
| FR-F-02 | フォルダの中にさらにフォルダを作成できる（階層の深さに上限なし） | Must |
| FR-F-03 | フォルダ名を変更できる | Must |
| FR-F-04 | フォルダを別のフォルダ（またはルート）へ移動できる。自分自身や自分の子孫への移動はできない | Must |
| FR-F-05 | フォルダを削除できる。中身（子フォルダ・ノート）がある場合は件数を示して確認し、中身ごと削除する | Must |
| FR-F-06 | 同じ階層に同名のフォルダは作成できない | Must |
| FR-F-07 | フォルダ画面で、子フォルダとノートを一覧表示する（フォルダを先に表示） | Must |
| FR-F-08 | 一覧の並び順を「名前順」「更新日時順」で切り替えられる | Should |
| FR-F-09 | 現在の階層位置（パンくず等）が分かり、上位階層へ戻れる | Must |

### 5.2 スキャン・取り込み

| ID | 要件 | 優先度 |
|---|---|---|
| FR-S-01 | カメラでドキュメントをスキャンし、新規ノートを作成できる | Must |
| FR-S-02 | スキャン時に書類の輪郭を自動検出し、台形補正（真上から撮ったような画像に補正）する | Must |
| FR-S-03 | 自動検出した輪郭の四隅を手動で調整できる | Must |
| FR-S-04 | 1回のスキャンで複数ページを連続撮影できる | Must |
| FR-S-05 | 写真アプリから1枚以上の画像を選択し、新規ノートとして取り込める | Must |
| FR-S-06 | 作成したノートは、スキャン開始時に開いていたフォルダに保存される | Must |
| FR-S-07 | ノートのタイトルは作成日時（例: `2026-09-28 10.30`）で自動設定される。ファイル名に使えない `:` は使わない。同じ階層に同名がある場合は末尾に ` (2)` などを付ける | Must |
| FR-S-08 | カメラ・写真へのアクセス許可がない場合、理由を説明し設定画面へ誘導する | Must |

※ 画像補正（白黒化・明るさ調整等）は、各OS標準スキャナ（iOS: VisionKit / Android: ML Kit）が提供する範囲で利用する。

### 5.3 OCR（文字認識）

| ID | 要件 | 優先度 |
|---|---|---|
| FR-O-01 | ページ保存後、自動的にOCRを実行しテキストを保存する | Must |
| FR-O-02 | OCRは日本語・英語（混在含む）を認識できる | Must |
| FR-O-03 | OCRは端末内で処理し、画像やテキストを外部に送信しない | Must |
| FR-O-04 | OCRはバックグラウンドで実行し、処理中もアプリ操作をブロックしない | Must |
| FR-O-05 | ページごとにOCRの状態（未処理・処理中・完了・失敗）を保持し、失敗時は再実行できる | Must |
| FR-O-06 | ページのOCRテキストを表示・コピーできる | Must |

### 5.4 ノート・ページ管理

| ID | 要件 | 優先度 |
|---|---|---|
| FR-N-01 | ノートを開き、ページ画像を左右スワイプで閲覧できる | Must |
| FR-N-02 | ページ画像をピンチで拡大・縮小できる | Must |
| FR-N-03 | ノートのタイトルを変更できる | Must |
| FR-N-04 | ノートを別のフォルダ（またはルート）へ移動できる | Must |
| FR-N-05 | ノートを削除できる（確認あり） | Must |
| FR-N-06 | 既存ノートに、スキャンまたは写真取り込みでページを追加できる（末尾に追加） | Must |
| FR-N-07 | ノート内のページの順番を並べ替えられる | Must |
| FR-N-08 | ノート内のページを削除できる（確認あり）。最後の1ページを削除する場合はノートごと削除するか確認する | Must |
| FR-N-09 | 一覧ではノートごとに1ページ目のサムネイル・タイトル・更新日時・ページ数を表示する | Must |

### 5.5 検索

| ID | 要件 | 優先度 |
|---|---|---|
| FR-Q-01 | 全ノートを対象に、タイトルとOCRテキストをキーワードで検索できる | Must |
| FR-Q-02 | 部分一致で検索でき、1文字のキーワードでも検索できる | Must |
| FR-Q-03 | 検索結果には、ノート名・所属フォルダのパス・一致箇所の前後テキスト（強調表示）を表示する | Must |
| FR-Q-04 | 検索結果をタップすると、該当ノートの一致したページを開く | Must |
| FR-Q-05 | 現在のフォルダ配下（子孫含む）に絞って検索できる | Should |

### 5.6 エクスポート

| ID | 要件 | 優先度 |
|---|---|---|
| FR-E-01 | ノートをPDF（全ページ画像を1ファイルにまとめたもの）として書き出せる。OCRテキストを透明テキストとして埋め込み、PDF内で検索・コピーできる | Must |
| FR-E-02 | ノートをMarkdown（OCRテキスト＋画像ファイルをzipにまとめたもの）として書き出せる | Must |
| FR-E-03 | 書き出したファイルはOSの共有シートで保存・送信できる | Must |
| FR-E-04 | 単一ページの画像を共有シートで書き出せる | Should |

### 5.7 本棚

| ID | 要件 | 優先度 |
|---|---|---|
| FR-V-01 | 本棚が1つもないとき（初回起動時）、本棚の作成画面を表示し、名前を入力して作成できる | Must |
| FR-V-02 | 設定画面から本棚を追加で作成できる | Must |
| FR-V-03 | 設定画面から開く本棚を切り替えられる。最後に開いた本棚を次回起動時に開く | Must |
| FR-V-04 | 本棚の名前を変更できる | Must |
| FR-V-05 | 本棚を削除できる（中身の件数を示して確認）。開いている本棚を削除した場合は別の本棚を開き、残っていなければ作成画面を表示する | Must |
| FR-V-06 | 同名の本棚は作成できない | Must |
| FR-V-07 | 一覧・検索・移動の対象は開いている本棚の中だけとする（本棚をまたぐ移動は行わない） | Must |
| FR-V-08 | ライブラリ画面で、開いている本棚の名前が分かる | Must |

### 5.8 ファイルとしての保存と外部変更の反映

| ID | 要件 | 優先度 |
|---|---|---|
| FR-X-01 | 本棚・フォルダ・ノートは端末上のフォルダとして、画面と同じ名前で保存する。ページはノートのフォルダ内の画像ファイルとして、ページ順に並ぶファイル名で保存する | Must |
| FR-X-02 | 本棚のフォルダを iOS の「ファイル」アプリ（このiPhone内 > Leaves）と、ケーブル接続時の Mac の Finder から閲覧・操作できる | Must |
| FR-X-03 | Android では、端末のファイル管理アプリから本棚のフォルダを閲覧・操作できる | Should |
| FR-X-04 | 外部でのフォルダの作成・名前変更・移動・削除を、アプリの起動時と前面に戻ったときにフォルダ・ノートとして反映する | Must |
| FR-X-05 | 外部でノートのフォルダに画像を追加・削除した場合や、ファイル名を変えてページ順を変えた場合、ページとして反映する。追加されたページは OCR する | Must |
| FR-X-06 | 外部でフォルダ（または本棚の最上位）に直接置かれた画像は、1枚ずつ新しいノートとして取り込む | Must |
| FR-X-07 | 外部で名前変更・移動されたノート・ページは同じものとして扱い、OCR 結果を引き継ぐ（OCR をやり直さない） | Must |
| FR-X-08 | 対応していないファイル（PDF・テキストなど）は無視し、変更・削除しない | Must |
| FR-X-09 | Leaves フォルダの直下に外部で作られたフォルダは、本棚として一覧に表示する | Should |

## 7. 非機能要件

### 7.1 対応環境

| ID | 要件 |
|---|---|
| NFR-E-01 | iOS / Android の両方で動作すること |
| NFR-E-02 | 最低対応OSバージョンは iOS 16.4 以上、Android 10（API 29）以上とする |
| NFR-E-03 | スマートフォンの縦向き表示を対象とする（タブレット・横向きは動作すればよい） |
| NFR-E-04 | Android はGoogle Play開発者サービスが利用可能な端末を対象とする（ML Kit の前提） |

### 7.2 性能

| ID | 要件 | 目標値 |
|---|---|---|
| NFR-P-01 | アプリ起動からフォルダ画面表示まで | 2秒以内 |
| NFR-P-02 | フォルダ画面の表示（1フォルダ内100件） | 1秒以内 |
| NFR-P-03 | 検索結果の表示（ノート1,000件・ページ5,000枚時点） | 1秒以内 |
| NFR-P-04 | スキャン完了から画面操作可能になるまで（OCR完了は待たない） | 2秒以内 |
| NFR-P-05 | 1ページあたりのOCR処理時間 | 3秒以内（目安） |
| NFR-P-06 | 1ページあたりの保存画像サイズ | 平均1MB以下（目安） |
| NFR-P-07 | 外部変更の確認（ノート1,000件・ページ5,000枚、変更なし時）。画面操作はブロックしない | 5秒以内 |

### 7.3 信頼性

| ID | 要件 |
|---|---|
| NFR-R-01 | 保存処理の途中でアプリが終了しても、データベースと画像ファイルの不整合（参照先のない画像・画像のないページ）を残さないこと |
| NFR-R-02 | OCRが失敗しても、ページ画像は失われないこと |
| NFR-R-03 | アプリ再起動時、処理中のまま中断されたOCRを再実行すること |
| NFR-R-04 | 外部変更で画像やフォルダが欠けたり、想定外のファイルが置かれたりしても、アプリは異常終了せず、残っているデータを表示し続けること |
| NFR-R-05 | アプリのデータベースが失われても、本棚フォルダの中身からフォルダ・ノート・ページ・OCR結果を復元できること |

### 7.4 オフライン・プライバシー

| ID | 要件 |
|---|---|
| NFR-S-01 | すべての機能がオフラインで動作すること |
| NFR-S-02 | ユーザーデータ（画像・テキスト）を外部サーバーへ送信しないこと。解析・広告SDKを組み込まないこと |
| NFR-S-03 | データはアプリの保存領域に保存する。他アプリからは、OSのファイル共有の仕組み（「ファイル」アプリ・Finder・ファイル管理アプリ）を通してだけ参照・変更できること |
| NFR-S-04 | カメラ・写真へのアクセスは、必要な操作を行った時点で許可を求めること |

### 7.5 ユーザビリティ

| ID | 要件 |
|---|---|
| NFR-U-01 | フォルダ画面から2タップ以内でスキャンを開始できること |
| NFR-U-02 | UIの表示言語は日本語とする |
| NFR-U-03 | OSのライトモード・ダークモードに追従すること |
| NFR-U-04 | 削除など取り消しのできない操作には必ず確認を挟むこと |

### 7.6 保守性・拡張性

| ID | 要件 |
|---|---|
| NFR-M-01 | TypeScript（strictモード）で実装すること |
| NFR-M-02 | データ層・ロジック層に単体テストを用意すること |
| NFR-M-03 | 将来の同期機能に備え、全データにUUIDと作成日時・更新日時を持たせること |
| NFR-M-04 | データベース構造の変更に備え、マイグレーションの仕組みを持つこと |
| NFR-M-05 | ソースコードと設計書は GitHub（SasaBranch/Leaves）で管理すること |

## 8. 制約条件

| No | 制約 |
|---|---|
| C-1 | フレームワークは Expo（React Native）+ TypeScript を使用する |
| C-2 | ネイティブモジュール（スキャナ・OCR）を使用するため、Expo Go ではなく開発ビルド（Development Build）で動作させる |
| C-3 | スキャンは OS 標準スキャナ（iOS: VisionKit / Android: ML Kit Document Scanner）を利用し、独自の画像処理は実装しない |
| C-4 | カメラを使う機能の動作確認は実機で行う（シミュレータ・エミュレータでは不可） |
| C-5 | 開発者は1名。外部サーバー・有料サービスは使用しない |

## 9. 前提条件

| No | 前提 |
|---|---|
| P-1 | 利用者は端末を1台のみ使用する（MVPではデータ同期を考慮しない） |
| P-2 | 端末の空き容量は利用者が管理する（容量不足時はエラーを表示する） |
| P-3 | OCRの精度は OS・ライブラリの性能に依存し、特に手書き文字は完全な認識を保証しない |

## 10. 将来拡張（MVP対象外）

| 候補 | 概要 |
|---|---|
| 同期・クラウド保存 | 複数端末でのデータ共有（Supabase 等） |
| バックアップ／復元 | 全データのzip書き出し・読み込み（機種変更対策） |
| タグ | フォルダとは別軸の分類・絞り込み |
| メモ編集 | ノートへのMarkdownメモ追記 |
| OCRテキスト修正 | 認識結果の手動修正 |
| 高精度手書き認識 | クラウドAI（Claude API 等）による手書き文字のテキスト化 |
| ゴミ箱 | 削除したノートを一定期間復元可能に |
| アプリロック | Face ID / 指紋による起動時ロック |
| 画像編集 | 保存後のトリミング・回転・フィルタ |
| フォルダ単位のエクスポート | フォルダ配下を一括書き出し |
| ストア公開 | App Store / Google Play での配布（プライバシーポリシー等の整備） |

## 11. 受け入れ基準（MVP完了条件）

以下をすべて満たしたとき、MVPを完了とする。

1. 5章の優先度 **Must** の機能要件がすべて実装され、iOS実機・Android実機の双方で動作する
2. 4.2の利用シーン S-1〜S-6 を実機で一通り実行できる
3. 7章の非機能要件のうち性能目標（NFR-P）を、テストデータ（ノート1,000件・ページ5,000枚）で満たす
4. テストフェーズで作成するテスト仕様書の項目がすべて合格している
