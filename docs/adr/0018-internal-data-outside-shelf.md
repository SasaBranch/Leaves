# 0018. 索引 DB・サムネイル・設定は、本棚の外の `Documents/.leaves/` に置く

- 状態: 承認
- 日付: 2026-09-28

## 背景
iOS のファイル共有（`UIFileSharingEnabled`）を有効にすると、アプリの `Documents` 全体が「ファイル」アプリ・Finder に見える。本棚ごとの索引 DB・サムネイル・「最後に開いた本棚」の設定を置く場所を決める必要がある。expo-sqlite の既定の保存先も `Documents/SQLite` で、そのままでは利用者に見えてしまう。

## 決定
- アプリの内部データは `Documents/.leaves/` にまとめる（名前が `.` で始まるため「ファイル」アプリでは表示されず、Finder でも隠しファイル扱いになる）
  - `settings.json`: 最後に開いた本棚の ID
  - `shelves/{shelfId}/index.db`: 本棚の索引 DB（`openDatabaseAsync` の `directory` 引数で場所を指定する）
  - `shelves/{shelfId}/thumbs/{pageId}.jpg`: サムネイル
- 本棚フォルダの中には、利用者に意味のあるもの（フォルダ・画像）と、小さな `.leaves.json` だけを置く
- 走査では、名前が `.` で始まるものをすべて無視する

## 検討した選択肢
- **本棚フォルダの中（`本棚/.leaves/index.db`）に置く** — 本棚フォルダだけを持ち運べば索引も付いてくるが、Finder でコピーしている最中に DB を書き換えて壊すおそれがある。索引は作り直せるので、持ち運ぶ価値は小さい
- **キャッシュ領域（`Paths.cache`）に置く** — OS に消されることがあり、そのたびに全体の走査とサムネイル生成（数千枚）が必要になる

## 結果
- 本棚フォルダの見た目が単純になり、DB を壊すおそれがなくなる
- 本棚の ID（`.leaves.json`）で内部データを探すため、本棚の名前を変えても内部データはそのまま使える
- 本棚が外部で削除された場合、その内部データは次回起動時に削除する
