# 0026. Android の「別の場所」の本棚は見送り、アプリ内の本棚だけにする

- 状態: 承認
- 日付: 2026-09-29

## 背景
要件定義書 v1.5 で本棚の保存場所を選べるようにした（FR-L-01〜08）。基本設計書 R-11 で、Android の別の場所（Storage Access Framework の `content://` のフォルダ）で今の実装の前提が使えるかを事前検証することにしていた。

expo-file-system（SDK 57）の Android 実装を確かめたところ、`content://` のフォルダでは次のことができない:
- `new Directory(親, 名前)` のように名前をつないで場所を作る（SAF の URI は名前をつないだ形になっていない）
- `Directory.create()`（`createDirectory` を使うよう例外になる）

Leaves のファイル操作（保存・名前変更・移動・走査・書き出し・ページ編集）は、どれも「本棚フォルダ ＋ 祖先の名前 ＋ ノート名 ＋ ページ番号」で場所を組み立てる前提で書かれている（詳細設計書 4.5）。

## 決定
- Android では「別の場所」の本棚を作る・開く・移す機能を出さず、アプリ内の本棚だけにする（R-11 の代替案どおり）
- iOS は予定どおり、iCloud Drive・端末内の任意のフォルダに対応する
- FR-X-03（Android でファイル管理アプリから本棚が見える）は満たせないまま残す（Should）

## 検討した選択肢
- **ファイル操作をすべて「子を名前で探してたどる」形に書き換える** — 走査・保存・移動・書き出しなどほぼすべての処理に及び、iOS 側の動きまで変える危険がある。Android の実機がなく、エミュレータだけで確かめることになる
- **Android のアプリ用の外部領域（`Android/data/…`）に置く** — Android 11 以降は他のアプリ（ファイル管理アプリを含む）から見えないため、外から見えるという目的を満たさない

## 結果
- Android の利用者は、本棚をアプリ内にしか置けない（外から見えない）
- 将来、Android で別の場所に対応する場合は、ファイル操作の場所の組み立てを1か所（`storage/paths.ts`）から「たどる」形に変える必要がある
