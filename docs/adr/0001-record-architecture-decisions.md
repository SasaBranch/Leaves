# 0001. 設計判断を ADR で記録する

- 状態: 承認
- 日付: 2026-09-28

## 背景
Leaves は要件定義 → 基本設計 → 詳細設計 → 実装の順で進めている。しかし設計書は作った時点からコードとのずれが始まり、AI と一緒に高速に変更していくと「なぜこうなっているか」が誰の頭にも残らない（ブラックボックス化）おそれがある。

## 決定
`docs/adr/` に設計判断を1件1ファイルで記録する。過去の記録は書き換えず、判断を変えるときは新しい記録を追加する。

## 検討した選択肢
- 設計書の改訂履歴だけで管理する — 何を変えたかは残るが、なぜ変えたか・何を捨てたかが残りにくい
- 記録しない — 1人開発でも、半年後の自分は他人と同じで理由を覚えていない

## 結果
- 設計の理由がコードの変更履歴と一緒に残る
- 判断のたびに短い文書を書く手間を引き受ける
