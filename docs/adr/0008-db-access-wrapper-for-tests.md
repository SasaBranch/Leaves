# 0008. DB アクセスを薄いラッパー経由にし、テストで差し替える

- 状態: 承認（実装方法は [0011](0011-serialize-db-access.md) で更新）
- 日付: 2026-09-28

## 背景
リポジトリ層の SQL・制約・トリガーは単体テストしたい（NFR-M-02）。しかし expo-sqlite はネイティブモジュールのため、Jest（Node.js）上では動かない。

## 決定
リポジトリは expo-sqlite を直接呼ばず、`run` / `get` / `all` / `transaction` の4つだけを持つ薄いラッパー（`Db` 型）を受け取る。アプリでは expo-sqlite、テストでは better-sqlite3 で `Db` を実装する。

## 検討した選択肢
- リポジトリをモックしてテストする — SQL そのものが検証されず、一番バグが出やすい部分をテストできない
- 実機でのみテストする — 自動化できない

## 結果
- 実行されるのと同じ SQL を Node.js 上でテストできる
- 抽象化の理由は「2つの実装（アプリ用とテスト用）が今すでに必要」という事実であり、将来の DB 差し替えに備えたものではない。ラッパーは4関数以上に広げない
- expo-sqlite と better-sqlite3 の SQLite バージョン差による挙動の違いは、実機での確認で補う
