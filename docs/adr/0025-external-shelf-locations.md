# 0025. 別の場所の本棚は、アプリの設定に参照を持ち、iOS はブックマークでアクセスを保つ

- 状態: 承認
- 日付: 2026-09-28

## 背景
要件定義書 v1.5 で、本棚の保存場所を選べるようにした（FR-L-01〜08。iCloud Drive、端末内の任意のフォルダなど）。これまで本棚は「アプリの Documents 直下のフォルダ」と決めていたので、見つけ方もアクセスの仕方もそれに頼っていた。

- iOS では、アプリの外のフォルダには、利用者がフォルダ選択画面で選んだときにだけアクセスが許される。再起動後も使うには、そのフォルダの「ブックマーク」を保存しておき、開くたびに解決してアクセスを始める必要がある。expo-file-system はフォルダ選択（`pickDirectoryAsync`）はできるが、ブックマークの保存・解決はできない
- Android では、選んだフォルダへの永続的な許可を expo-file-system が OS に登録する
- 組み立て中のノートを置く作業用フォルダ（ADR 0016・詳細設計書 9.1）をアプリ内に置くと、本棚が別のボリューム（iCloud Drive など）にあるとき、完成したノートを1回の移動（名前の付け替え）で置けない

## 決定
- 別の場所の本棚は、アプリの設定（`settings.json`）に「ID と場所への参照」を持つ。参照は iOS ではブックマーク、Android ではフォルダの URI。アプリ内の本棚は、これまでどおり Documents の走査で見つける
- iOS のブックマークと、iCloud のファイルのダウンロードの依頼のために、小さなネイティブモジュール `modules/folder-access`（iOS のみ）を作る
- 開けない参照（許可切れ・見つからない）は一覧から自動で消さず、「開けません」と示して、選び直すか一覧から外すかを利用者に選んでもらう
- 作業用フォルダは、本棚フォルダの中の隠しフォルダ `.leaves-work/` に移す
- 本棚の場所の移動は、コピーして件数を確かめてから元を消す（別のボリュームへは名前の付け替えで移せないため）

## 検討した選択肢
- **本棚をすべて設定に登録する（アプリ内も）** — アプリ内の本棚は外部で作られたフォルダも本棚にする（FR-X-09）ため、走査で見つける方が合っている
- **iCloud の本棚はアプリの iCloud コンテナ（アプリ専用の iCloud フォルダ）に置く** — 利用者が「ファイル」アプリで好きな場所を選ぶ、という要件（Q-12）に合わない。開発者アカウントの iCloud の設定も必要になる
- **開けない参照を自動で一覧から消す** — 一時的に iCloud にアクセスできないだけで本棚が消えたように見え、利用者を驚かせる

## 結果
- 本棚フォルダの中身の構成・外部変更の反映（ADR 0016〜0022）は、場所に関係なくそのまま使える
- iOS のブックマークと iCloud の未ダウンロードの見え方は、シミュレータではフォルダ選択画面を操作できないため、iPhone 実機で確かめる（基本設計書 R-10）
- Android の別の場所（Storage Access Framework）で、今の実装の前提（名前をつないで場所を組み立てる）が使えるかは事前検証する（R-11）
