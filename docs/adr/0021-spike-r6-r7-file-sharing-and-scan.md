# 0021. 事前検証 R-6・R-7 の結果、フォルダの更新日時は `new File(フォルダ).modificationTime` で読む

- 状態: 承認
- 日付: 2026-09-28

## 背景
基本設計書 11 章 R-6（ファイル共有での見え方）・R-7（外部変更の確認の走査時間）を、iOS 27 シミュレータ（iPhone 18 Pro）で確認した（#38）。テストデータはノートブック20件 × ノート50件（計1,000件）、各ノートに画像5枚と、OCR 結果（1ページ800文字）入りの `.leaves.json`。

## 結果
**R-6（見え方）**
- `UIFileSharingEnabled`・`LSSupportsOpeningDocumentsInPlace` で、「ファイル」アプリの このiPhone内 に「Leaves」が表示され、`Documents` の中身が見えた
- 名前が `.` で始まるフォルダ・ファイルは表示されなかった（ADR 0018 のとおり内部データを隠せる）

**R-7（走査時間。2〜3回の計測値）**

| 方法 | 1,020フォルダ分 |
|---|---|
| ノートブック20件の `list()`（ノートのフォルダを見つける） | 450〜710ms |
| `Directory.info().modificationTime` | 2,100〜3,600ms |
| `new File(フォルダの uri).modificationTime` | 590〜990ms |
| 全ノートの `list()`・各画像のサイズと更新日時・`.leaves.json` の読み込み（DB を作り直すとき） | 5,500〜10,100ms |

`Directory.info()` は、中のすべてのファイルのサイズを合計する（ネイティブの実装で `subpathsOfDirectory` をたどる）ため遅い。

**expo-file-system の振る舞い（node の偽物に合わせる。ADR 0019）**
- `list()` が返す名前は **NFD**（濁点が分かれた形）。DB・入力の名前（NFC）と比べる前に `normalize('NFC')` する
- 日本語・空白・`#` `%` `()` を含む名前も扱える（URI はパーセントエンコードされる）
- `Directory.move(存在しない Directory)` はその場所へ移動する。移動元の `Directory` オブジェクトの `uri` は **更新されない**
- 存在するフォルダへの `move` は結果が不安定だったため使わない（移動先は常に「存在しないフルパス」で渡す）
- 既存の名前への `rename` は例外になる。大文字・小文字だけの `rename` はできる
- ファイルの `rename` で更新日時は変わらない

## 決定
- フォルダの更新日時は `new File(フォルダの uri).modificationTime` で読む（`Directory.info()` は使わない）
- 変更なし時の走査は、ノートブックの一覧を省けるため約 0.6〜1 秒の見込みで、NFR-P-07（5秒）を満たす。実機で改めて計測する（#44）
- 走査はJS スレッドで同期的に動くため、50フォルダごとに `await` で他の処理（画面の描画・操作）に順番を譲る
- DB を作り直す全体の走査（5〜10秒）は、DB がない・壊れているときと v1.0 からの移行時だけなので許容する（画面表示は止めない）
- ファイルシステムから得た名前は必ず NFC にしてから使う
