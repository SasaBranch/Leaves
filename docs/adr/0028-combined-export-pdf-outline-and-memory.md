# 0028. まとめて書き出しの PDF は、しおりを辞書で組み立て、ページ数の上限は設けない

- 状態: 承認
- 日付: 2026-09-30

## 背景
要件定義書 v1.6 で、ノートブック直下の複数のノートを1つの PDF にまとめて書き出せるようにした（FR-E-05〜09）。基本設計書 R-12 で、次の2点を事前に確かめることにしていた。

- pdf-lib は PDF 全体をメモリに持って組み立てるため、ページ数が多いとメモリが足りずに落ちるおそれがある
- pdf-lib にはしおり（アウトライン）を作る関数がない

## 確かめたこと（#47）
- **メモリと時間**: iOS 27 シミュレータ（開発ビルド）で、250 ノート・250 ページ（1ページ約 0.9MB。実物のノートより重い）をまとめて書き出した。PDF は 229MB、約 8 秒で共有シートが開き、アプリは落ちなかった。書き出し中のメモリの増加は約 490MB。Mac の node で pdf-lib だけを動かした場合も、250 ページ（PDF 163MB）で約 420MB と、PDF の大きさのおよそ 2.5 倍に収まった
- **しおり**: PDF のカタログに `/Outlines` と各項目の辞書（`/Title` は UTF-16、`/Dest` は各ノートの最初のページ）を直接組み立てた。書き出した PDF を読み戻し、49 ノートのしおりが並べた順に、正しいページを指していることを確かめた（自動テストでも確認）

## 決定
- しおりは PDF の辞書を直接組み立てて付ける（詳細設計書 9.14 のとおり）
- 1回に書き出せるページ数の上限は、今は設けない。250 ページ程度なら iPhone のアプリの使えるメモリに余裕がある見込みのため
- 取り消しは1ページごとに確かめる（長い書き出しでも、すぐに止められる）

## 結果
- iPhone 15 実機で、実物のノート約 250 ページの書き出し（テスト仕様書 T-E-15）を確かめる。落ちる・遅すぎる場合は、上限を設けて知らせる（基本設計書 R-12 の代替案）
- 数百 MB の PDF になると、共有先（メールなど）で送れないことがある。これはアプリでは制御しない
