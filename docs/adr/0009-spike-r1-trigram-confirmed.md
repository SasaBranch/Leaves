# 0009. 事前検証 R-1 の結果、trigram への LIKE 1本の検索を維持する

- 状態: 承認
- 日付: 2026-09-28

## 背景
ADR 0004 で「検索はすべて trigram テーブルへの LIKE で行う」と決め、同梱 SQLite で trigram が使えるか・1〜2文字の全件走査が性能要件（NFR-P-03: ページ5,000枚で1秒以内）に収まるかを実装初期に検証することにしていた（#2）。

## 検証内容
- expo-sqlite 57 の同梱 SQLite は 3.50.3。trigram トークナイザは 3.34 以降で使える。FTS5 は iOS / Android とも既定で有効（`expo.sqlite.enableFTS` が `false` でない限り `-DSQLITE_ENABLE_FTS5=1`）
- `spikes/r1-trigram-search.js` で、詳細設計書 6.2〜6.4 のスキーマ・トリガー・検索 SQL をそのまま使い、ノート1,000件・ページ5,000枚（1ページ400文字）を Node.js（better-sqlite3、SQLite 3.53.4、Mac）で計測した

| キーワード | 文字数 | 件数 | 中央値 |
|---|---|---|---|
| 値 | 1 | 100 | 3.9ms |
| 固有 | 2 | 100 | 3.9ms |
| 固有値 | 3 | 100 | 3.9ms |
| 特性方程式 | 5 | 100 | 4.1ms |
| ぬゅ（該当なし） | 2 | 0 | 3.2ms |
| 100%（特殊文字） | 4 | 0 | 2.2ms |

- タイトル変更トリガー・CASCADE 削除時のトリガーで索引が追従することも確認した

## 決定
ADR 0004 の方式（trigram テーブルへの LIKE 1本）を維持する。

## 結果
- 目標（1秒）に対して約250倍の余裕がある。スマホの CPU が Mac の10倍遅くても十分収まる
- 実機での最終確認は性能計測（#33）で行う
